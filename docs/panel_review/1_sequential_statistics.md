**Referee report, Professor 1 (sequential testing and e-values)**

**Verdict.** Theorem thm:gate is correct as stated, the proof is sound, and `adaptive_audit.py` implements the stated e-process with the right factors and the needed restriction that the alternative is below tolerance. The errors I found are one real inconsistency with the companion BIS paper on the cost of anytime validity, a few gaps between what the text says and what the code does, and some loose statements in the supplement. Recommendation: **minor revision** for the JPC paper. Finding 1 is **major** for bis_ifc_full.tex.

**What I checked and found correct**
- **Direction of the test.** The null is H_i: r_i ≥ τ_i, and certifying means rejecting it. A success multiplies the evidence by q/τ < 1 and a failure by (1-q)/(1-τ) > 1. This matches the code at adaptive_audit.py:43-45.
- **Supermartingale identity.** I re-derived p·q/τ + (1-p)(1-q)/(1-τ) = 1 + (p-τ)(q-τ)/(τ(1-τ)) (jpc_main.tex:73). It is at most 1 for every p ≥ τ exactly when q ≤ τ, so the process is valid for the whole composite null, not just the boundary point. The code enforces q in [0, τ) at adaptive_audit.py:41.
- **Proof.** Ville's inequality applied conditionally at the registration time σ_i, with w_i and the null indicator known at σ_i, gives P(A_i ∩ H_i) ≤ α E[w_i 1{H_i}]. Summing over coordinates with monotone convergence and using Σw_i ≤ 1 on every path gives the bound. This holds under registration that depends on the past, interleaving and optional stopping.
- **Weights (Prop prop:weights).** The Lagrange solution w_i ∝ c_i/a_i is correct and the objective is strictly convex. `planned_weights` matches it. Weights produced by `planned_weights` register without floating-point rejection in the four plans I tried.
- **Zero-success budget, by hand.** For τ=.12, α=.05, w=.5: log 40 / (-log .88) = 3.6889/0.12783 = 28.86, so the budget is 29. The code returns 29 and the test crosses at trial 29. For w=1/8 the budget is 40, matching main line 88 and supplement line 22. Equal weights reproduce the Clopper-Pearson zero-success count, as claimed.
- **Tests.** All 15 pass with `-o addopts=''`. The toy JSON matches Table tab:new-audit.
- **BIS Prop prop:anytime.** The mixture martingale, Ville step and inversion into a confidence sequence (bis_ifc_full.tex:1069-1083, 2516-2524) are correct.

**Findings**

1. **MAJOR (verified). bis_ifc_full.tex:1129-1134 and Table tab:anytime.** The paper says certifying τ=10⁻³ "needs ... 12,417 when the run is monitored throughout" and tells institutions to "budget for the second number". That figure comes only from choosing a uniform Beta(1,1) prior. It is not a cost of optional stopping. With zero successes the mixture e-value is E_prior[(1-p)^B]/(1-τ)^B, which is at most (1-τ)^{-B}, with equality for a point alternative at 0. That point alternative is the q=0 likelihood-ratio e-process of JPC Prop prop:cost. It is anytime-valid and certifies at 2,995, the same count as the fixed-sample test. I checked this in code: `zero_success_budget(.001,.05,1)` = 2995 and `certification_replicates(.001,.05)` = 12417. The two companion papers therefore make contradicting claims. Fix: replace the sentence with "With the uniform mixture used here, anytime certification needs 12,417 successless attacks. A predeclared point alternative at zero risk gives an anytime-valid test that certifies after 2,995, the fixed-sample count, but it can never certify once a success is seen. The larger figure is the price of staying able to certify after successes, not of monitoring itself." Qualify the "4.1" ratio column in the same way.

2. **MINOR (verified). Paper and code disagree on when certification holds.** jpc_main.tex:60 says a coordinate is certified "on first crossing". But `AuditCoordinate.certified` (adaptive_audit.py:27-29) checks the current value, and `observe` keeps accepting draws. A success after crossing un-certifies it: I checked, and `eligible` then returns False. This is still valid, because it certifies on a subset of the crossing event, but it is not the rule the theorem covers. Fix: add `crossed: bool = False`. In `observe`, raise if `self.crossed` is already set, and set `self.crossed = self.crossed or self.log_e >= self.threshold`. Have `certified` return `self.crossed`.

3. **MINOR (verified). `zero_success_budget` can be off by one.** At exact boundary cases the budget differs from the trial where `observe` actually crosses. Over 20,000 cases with τ = 1-(αw)^{1/B}, it was one trial too low 2,548 times and one too high 2,048 times. For example, τ=1-2^{-1/2}, α=.125, w=1 gives a budget of 7, but the audit crosses at 6. Supplement line 22 says the code "checks the boundary for floating-point edge cases". It does not. Fix: after computing `n = ceil(...)`, step through the real accumulation: `while n > 1 and (n-1)*a >= thr: n -= 1` and `while n*a < thr: n += 1`. Or run `observe(0, 0.0)` until it crosses and return `trials`. Either way, the docstring's "least trials" claim should match what `observe` does.

4. **MINOR (concern). The code does not prevent spending the α budget twice.** `AuditCoordinate` is a mutable dataclass. `coord.weight = 1.0` after registering with weight .01 lowers the threshold (I checked). A coordinate built directly skips the budget check, and each new `AdaptiveAudit` starts a fresh α. Fix: use `@dataclass(frozen=True)` for name, tolerance, weight and alpha, and keep the mutable counters in a separate state object. Say in the docstring that one programme must use one gate instance. The code also does not record the order of bets, sampling-unit IDs or model versions, although jpc_network.tex:28 says a release record needs them. Either log them in `observe` or remove the suggestion that the code enforces this.

5. **MINOR. jpc_main.tex:76, "The null status and allocation are known at registration."** Nobody knows the null status. It is fixed at registration. Replace with: "Because (θ_i, j_i), τ_i and w_i are F_{σ_i}-measurable, so is 1{H_i}; set w_i = 0 on {σ_i = ∞}." Also add "the index of the coordinate audited next is predictable" to the theorem's list of conditions. The proof uses this, and "stopping or continuation decisions" only implies it.

6. **MINOR. The abstract says "exceeds" but the theorem says "at least".** Line 19 reads "whose true success risk exceeds its tolerance", while eq:family and the supplement (line 16) use r_i ≥ τ_i. Replace with "whose true success risk is at least its tolerance".

7. **MINOR. Supplement line 11: the relaxed denominator also needs a tighter bet range.** If τ_i is replaced by τ'_i = τ_i-δ_i, validity requires q_{i,k} in [0, τ'_i). An alternative in [τ'_i, τ_i) makes the expected factor greater than 1 for p > τ'_i. Add: "and restrict the alternative to $q_{i,k}\in[0,\tau_i-\delta_i)$."

8. **MINOR. Supplement lines 9 and 14 have wording errors.**
   - Line 9 says "This is the exact condition needed". The condition is sufficient, not necessary. Replace with "This condition suffices".
   - Line 14 says H is "observed with equal probability at registration". If H is observed it is in F_σ, and the conditional null is then fine. Replace with "a hidden bit H∼Bernoulli(1/2), drawn at registration and not observed".

9. **MINOR. jpc_evidence.tex:58: the second toy experiment says little.** The streams are independent, so registering only when the first passes changes nothing about the null stream's law. The 0.00526 rate is just another estimate of the single-coordinate rate. Say so. A more telling check would let the bet on the null stream depend on its own past, such as a clipped running estimate, together with the registration rule.

10. **MINOR. tests/test_adaptive_audit.py:54: the Monte Carlo check is weak.** The bound `<= .07` at α=.05 with 2,000 runs is four standard errors of slack. It would pass an error rate near 0.065. Add an exact check over a grid of p ≥ τ and q < τ: `p*q/tau + (1-p)*(1-q)/(1-tau) <= 1 + 1e-12`. Tighten the Monte Carlo bound to `.05 + 3*sqrt(.05*.95/runs)`.

11. **MINOR. bis_ifc_full.tex:1116: the text misdescribes the monitoring study.** It says the institution "stops the moment the bound falls below the truth". The institution does not know the truth. What the study measures is whether the bound falls below the true risk at any of 20 looks. Rephrase to say that.

12. **MINOR. sequential.py:59: the bisection returns the midpoint.** It should return the excluded side for the upper end, so the reported bound never sits inside the rejected region by up to 5e-11. The effect is negligible but easy to fix.

The pooled-risk result (Prop prop:pool) is correct: with q^{m-1} ≤ ν, each single release leaves q^{m-1} candidates and the pool identifies the record. Prop prop:cost and the 6/(π²i²) remark (threshold growing as 2 log i + O(1)) are also correct.
